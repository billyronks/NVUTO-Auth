# Security reporting

Do not post live credentials, recovery links, database dumps or personal data in public issues.

GitHub private vulnerability reporting is enabled for [billyronks/NVUTO-Auth](https://github.com/billyronks/NVUTO-Auth). Report suspected vulnerabilities through [its private reporting form](https://github.com/billyronks/NVUTO-Auth/security/advisories/new). This repository does not claim a monitored security email address. If private reporting is unavailable, contact the owner through a verified private channel and ask for a secure reporting method before sharing details.

Provide the affected version, minimal reproduction using synthetic identities, impact, and any proposed fix. Supported security fixes target the current v0.1 line. An acknowledgement SLA is not promised until maintainers establish one. Deployment operators own incident response, credential rotation, backups, data protection and local retention policies.

The historical HR snapshot is excluded from distribution and is not supported or safe to deploy. Public source and container builds must exclude reference/, .local/, .cache/, .env and private attachments. The target repository had no published refs when this standalone source was prepared for initial publication. Only the reviewed public-source allowlist is committed. This does not establish the state of any other repository, deleted history or existing deployment.
